# Paper 模板 — 原创研究论文（非综述）

适用：原创研究论文（非综述）。改写 MD 时**必须保留每一条** `![](images/xxx.png)` 图片引用和论文元数据，**一条都不许丢**；删除原文段落（用自己的话概括）和参考文献列表。

---

## Frontmatter（必填）

笔记顶部写入 YAML frontmatter。每个字段**高度提炼为一句话**，来自原文而非摘要复制；数值必须来自原文。

```yaml
---
title: "{论文标题}"
tags:
  - 论文笔记
  - {领域标签，如 ISFET / 传感器 / 测量}
source: "{期刊/会议名}"
author: "{第一作者} 等，通讯 {通讯作者}"
year: "{年份}"
doi: "{DOI}"
zotero_key: "{item_key}"
theme: "一句话：论文解决什么问题"
method: "一句话：核心方法/器件原理"
material: "一句话：研究对象/材料/样品体系"
performance: "一句话：核心性能指标与关键数值"
key_finding: "一句话：最关键发现"
relevance: "一句话：与我研究的关联"
---
```

> **提炼规则：** theme / method / material / performance / key_finding / relevance 每字段一句话。**禁止整段复制摘要**；performance 关注数字（灵敏度、检出限、线性范围等），便于日后横向对比。

---

## 头部信息行

标题（`# {论文标题}`）下方紧跟一行信息行：

`**作者:** {作者} | **期刊/年份:** {期刊}, {年份} | **DOI:** {doi}`

## 板块结构（IMRaD 骨架）

### 1. `## Author / 作者背景`

**第一作者：** 判断是否博士生，记录研究方向。
**通讯作者：** 记录研究方向 + 单位。

> **H-index 规则：** 作者数 ≤ 10 → 可搜 H-index，H-index > 20 备注"该领域有影响力"。作者数 > 10 → 跳过，仅根据单位信息简评。

### 2. `## Key words / 关键词`

列出关键词（中英对照），判断与用户研究方向的相关性。

### 3. `## 一句话摘要`

正文第一个内容板块。用 **1 句话**写清：**研究对象/器件是什么 → 用什么方法实现 → 得到什么关键结论**。这是 Obsidian 列表/卡片视图最重要的字段，必须通顺、独立可读。

### 4. `## Abstract / 摘要`

三要素：**① 方法 ② 效果**（关注数字，便于横向对比）**③ 创新点**。

### 5. `## Introduction / 引言`

**背景与不足**（以前怎么做 + 不足）→ **本文方法** → **本文主要工作**。
补充 **研究缺口定位**：这个领域尚未解决的关键问题是什么（比"不足"更具体，指向本文动机）。

### 6. `## Experimental method / 实验方法`

结构化小节，按论文实际内容取舍：

#### 6.1 实验/器件设计概述
- **总体思路**：为什么这么做。
- **设计逻辑**：如何实现目标（如"通过 X 结构实现 Y 性能"）。

#### 6.2 材料与试剂
材料体系 / 试剂配方 / 纯度 / 来源。

#### 6.3 制备/实验流程
步骤 1 → 2 → 3，标注关键参数：温度、浓度、时间、比例。保留流程图/装置图。

#### 6.4 仪器与表征
仪器型号 / 厂商 / 测试条件。

#### 6.5 关键公式 / 指标（按需增减）
文章有核心公式/指标时，按"公式说明 + 公式 + 公式拆解"结构添加；没有则不写。
- **公式说明 1：** 这条公式做什么用（如计算灵敏度、检出限、信噪比）。
- 公式本身。
- **公式拆解 1：** 关键符号含义 / 对应实验中的哪一步。

> **公式规则：** 原文可靠才保留；乱码/残片**不强行解释**，也不为占位符编造符号拆解。

#### 6.6 方法优势 / 局限
- **优势：** 相对已有方法好在哪里（更快 / 更便宜 / 更灵敏 / 更简单）。
- **局限：** 适用范围、误差来源、可重复性疑虑。

### 7. `## Result and Discussion / 结果与讨论`

结构化小节：

#### 7.1 关键性能指标（数字优先）
灵敏度 / 检出限 / 线性范围 / 响应时间 / 重复性…（按论文实际，**数字必填**）。保留关键数据图。

#### 7.2 主要发现 + 原文引用（成对，按需增减）
每条主要发现紧邻至少一条真实原文引用：
```
- **主要发现 1：** ...
- **原文引用 1：**
> "原文"（PDF 第 n 页）

- **主要发现 2：** ...
- **原文引用 2：**
> "原文"（PDF 第 n 页）
```

> **引用规则：** 引用必须**真实出现在** MinerU MD 或原 PDF 中；定位不到写「未在当前全文中定位到可核验原句」，**严禁根据中文摘要反向生成英文 quote**；页码仅在可靠映射时写。

#### 7.3 分析逻辑与机理讨论
作者如何解释结果（机理、趋势成因、验证策略）。

#### 7.4 与他文/商品对比
保留对比表；对比维度：灵敏度 / 检出限 / 成本 / 复杂度。

### 8. `## Conclusion / 结论与个人评注`

**作者结论：** ... **未解决问题：** ... **未来方向：** ...
**个人评注：**（工程价值 vs 科学创新）

### 9. `## 我的判断`

- **最有启发的点：** ...
- **可借鉴的方法：** ...
- **可继续追问的问题：** ...
- **与我的研究关联：** ...

## 证据分层

原文（MinerU MD / 原 PDF）= **证据层**；本笔记 = **理解层**。
- 性能数值、公式、引语**必须回原文核对**，不得凭空转述。
- AI 转述用普通正文；原文引用用引用块 `>`，排版上可区分。
- 无法核验的内容明确标注"未核验"，不得伪装成原文。

## 图片处理

- MinerU 图片在 `images/` 中，MD 中以 `![](images/image_xxx.png)` 引用。
- 将**所有**图片引用移到对应板块文字附近，上方加描述性标题（如 `**Figure 1:** xxx`）。
- **没有例外：** 原文 MD 中出现的每一条 `![](images/xxx.png)` 都必须出现在改写后的笔记里。
- 放不进对应板块的图片，在 `## Conclusion` 之后、尾部标注之前追加一节 `## 全部图片 / 图片附录`，把剩余图片全部列出（正文引用 + 附录 = 原文全部图片）。
- 改写完成后逐条核对：原文每条图片引用都必须出现在新笔记（正文或附录）中，缺失即视为错误，需补齐。
- 直接用原始路径，不需要重命名或创建新目录。
